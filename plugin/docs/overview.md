# GitHub

Read and write GitHub repositories from agent workflows — issues, pull
requests, branches, releases, file contents, and Actions workflow runs.

## What it does

The `github` plugin exposes GitHub repository operations as safe functions.
Once the plugin is enabled on an agent, those functions become globals inside
the sandbox — callable from any workflow with no imports.

Typical uses:

- **Issue triage** — open, label, and comment on issues; classify inbound
  feedback with the `llm` plugin, then file the result as a GitHub issue.
- **Pull-request automation** — open PRs from generated branches and post
  review comments.
- **Release + changelog** — cut a release and write release notes generated by
  an LLM.
- **CI visibility** — list workflow runs, fetch artefacts, and surface failed
  job logs back into a chat session.

## Function groups

| Group | Examples |
|---|---|
| Issues | `createIssue`, `getIssue`, `addIssueComment`, `addIssueLabels`, `listIssueComments` |
| Pull requests | `createPullRequest`, `getPullRequest`, `addPrComment` |
| Branches | `createBranch`, `getBranch`, `listBranches` |
| Files / content | `getFileContent`, `createOrUpdateFile`, `listDirectoryContents` |
| Releases | `createRelease`, `getRelease` |
| Workflows / Actions | `getWorkflowRun`, `cancelWorkflowRun`, `downloadWorkflowArtifact`, `getWorkflowJobLogs` |
| Repository | `getRepo`, `getRepoContributors` |

The full function list (parameters, return types, credential needs) is
available per-plugin via the `plugins:info` command in the dashboard.

## Credentials

This plugin needs a **GitHub personal access token** (the `github`
credential provider). Every function declares
`requiredCredentials: ["github"]`, so none of its functions are callable
until a credential is connected.

| Provider | Type | How to get it |
|---|---|---|
| `github` | token | Create a classic token at `github.com/settings/tokens`. Grant the **`repo`** scope (add **`workflow`** if you touch Actions files). |

Connect it inline from the plugin row (the "set credentials" affordance wires
to the standard token credential flow), or via the CLI:

```bash
orgsdk credential set github default ghp_your_token_here
```

## Using it in a workflow

```typescript
// Open an issue from structured data
const issue = await createIssue({
  owner: "myorg",
  repo: "myrepo",
  title: "Bug: checkout fails on Safari",
  body: "Steps to reproduce...",
  labels: ["bug", "frontend"],
});

// Comment on an existing PR
await addPrComment({
  owner: "myorg",
  repo: "myrepo",
  pullNumber: 42,
  body: "Deployed to staging ✅",
});
```

## Notes

- All functions take an `{ owner, repo, ... }` options object — the repository
  is addressed per-call, not configured globally.
- Read operations (`get*`, `list*`) are tagged `readonly` and safe to use in
  discovery workflows.
- This plugin has no `guides/` reference yet; agent usage patterns can be added
  there later (agent-facing) without touching this human-facing doc.
